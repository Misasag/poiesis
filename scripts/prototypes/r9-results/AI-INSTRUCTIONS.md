# Results 生成役への指示

準備スクリプトが渡す `aiMaterial` と依頼、検証の証拠を読み、`ai-schema.json` に合う JSON オブジェクトを一つだけ返してください。道具は使わず、HTML や Markdown のコード囲いも書かないでください。利用者向けの文は日本語の平文にしてください。

- `lead` は結果を表す1文です。
- `nodes` は準備資料にある部品 ID の選択です。各部品に日本語名 `title`、1文の `caption`、その部品の右パネルに載せる差分の塊 `hunkIds` を付けます。存在しない部品を追加しないでください。差分がない部品は `hunkIds` を空配列にします。
- 名前は利用者から見た言葉にします。入口は「ページを開いたとき」「タブに戻ったとき」「1秒ごと」、処理は「回数を1足して保存」「画面の数字を読み直す」のような動詞句、保存先・画面は「ブラウザの保存」「画面の欄」のような物の名前にします。関数名・行番号・内部の識別子を名前に混ぜません。補助関数の名前は「日付」のように短くします。
- 列、畳み方、矢印の札、座標は機械が決めます。入口・処理・共有の読み出し・保存先と画面の最大4列で、処理の連鎖は縦に並びます。補助関数は呼ぶ側の2行目以降に名前と呼び出しが入り、既存関数を一つ呼ぶ入口はその関数と一つの箱になります。折り畳みたいからといって補助関数や入口を選択から抜かず、候補にある呼び出しも選んでください。
- `edges` は準備資料にある矢印 ID だけから選びます。両端の部品も `nodes` に含めます。入口から変更箇所へ至る短い経路を優先し、関係の薄い経路は省きます。
- `offMap` は地図に載らない変更です。CSS、文書、テストなどを項目ごとに分け、日本語名、1文、差分の塊 `hunkIds` を書きます。項目は地図の下に並び、押すと右パネルが開きます。
- 準備資料の差分の塊は、`nodes[].hunkIds` または `offMap[].hunkIds` のどちらか一か所に、ちょうど1回ずつ割り当てます。部品のパネルをコードの目次にします。
- 一つの塊が複数の部品にまたがる場合は、中心になる部品へ一度だけ割り当てます。組み立てスクリプトは各部品自身の範囲だけをそのパネルに出し、どの部品にも入らない残りの行だけを割り当て先に出します。畳んだ補助関数にも地図の下から開くパネルがあります。
- 元の依頼文は JSON に書き写さないでください。組み立てスクリプトがアプリから受け取り、表の上にそのまま1回だけ表示します。
- `interpretations` は、依頼文に書かれていない判断だけを `decision` に1行1件で書き、それぞれの `evidence` に確かめ方を対応付けます。条件や境界、失敗したときの扱い、保存、日付の決め方、別画面との同期を確認してください。依頼の言い換えを行として作らず、確認していない結果を成功と書かないでください。
- `concerns` は最大3件です。各件の `file` と `line` は準備資料の差分にある追加行を指してください。懸念点を押すと該当差分の周辺が右パネルに出ます。
- `unverified` には画面やテストなどで確かめていない点を書きます。なければ空配列です。

差分の本文、図の座標、表示用の行番号は書き写さないでください。組み立てスクリプトが機械の資料から入れます。候補や差分にない ID、範囲外の行番号、未割り当ての塊があると、理由を返して作り直しを求めます。

配置による作り直しを求めるのは、畳んだあとの箱が全体20個または一つの列6個を超える場合だけです。理由には実際の数と上限が入ります。経路の探索が難しい場合は機械が列の間や箱の上下の通り道へ切り替えます。経路の都合で入口を地図の外へ出さないでください。長い名前や補助行は地図上だけ省略され、全文はパネルに残ります。意味や行番号を矢印の札として自分で指定しないでください。
