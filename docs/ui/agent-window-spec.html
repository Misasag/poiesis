Agentサイドバーの完成契約

サイドバーは単なるSessionリンク集ではなく、Local Agentの作業状況を横断して把握し、次の会話へ移るためのナビゲーションである。ユーザーは細かな画面遷移を覚えず、同じ場所から作成、検索、再開、整理、状態確認を行える。

領域必須の振る舞い失敗させない条件
New Chat未送信のNew Agent画面を開き、ComposerのRepository picker、branch picker、Run onで作業対象を確定してから送信する連打で空Sessionを増殖させない。Repository変更だけではTaskを開始しない
Searchタイトルと保存済み会話本文を絞り込み、選択時に該当Sessionを開くコード検索と混ぜない。Archivedも検索対象だが区分は保つ
WorkspaceRepositoryごとにSessionをグループ化する。New AgentではNo RepoまたはOn This PCのRepositoryを選び、branchを確定するRepositoryを暗黙固定しない。Worktree／Cloud／Remote SSHの利用可能に見える操作は出さない
Session行選択、タイトル、更新時刻、pin、running／attention／unread状態を一行で判別できる色だけに依存せず短い状態文も付ける。実行中Sessionはarchive不可
三点メニューpin解除、rename、archiveを提供する。Archivedではrestoreと確認付き永久削除へ置き換える削除はArchivedからのみ。Agent runtime、Task、Resultsも同じSession単位で破棄する
幅と折りたたみ196〜420pxをdrag／矢印キーで変更し、double clickで既定幅へ戻す。折りたたみ時もNew ChatとSearchを残す幅と開閉状態をWindow単位で復元し、Agent／Results切替で変えない

状態表示選択時

Resultsの単位と表示契約

Resultsは、変更を伴う完了Taskまたは失敗・キャンセルTaskを手掛かりに成果を確認するSession内の画面である。変更なしで完了したTaskは要件レールにも文書にも出さない。アプリが固定する枠は、実行Taskの切替リスト、本体キャンバス1つ、その下の短いComposerだけ。同じSessionの他Taskは切替リストから選び、左サイドバーのSession一覧とは分ける。第一完成点では、本体キャンバスの中身はSkillsが返すHTML文書1つとし、アプリはその文書を表示する枠だけを持つ。HTMLを節やカードへ分解せず、見出し、図、比較、引用などの内部構成を強制しない。

Resultsで何を一つの見どころとして分類するかはSkillsが決める。その分類は実行Taskの境界を写す必要がなく、複数Taskをまとめても、一つのTaskを複数の見どころに分けてもよい。Markdownは第一完成の必須形式にしない。将来の入力形式、またはMarkdownをHTMLへ変換するSkillとして追加できる。

質問スレッドは選択中の実行Taskと表示中のSkill HTMLをscopeに持ち、HTML文書やアプリが確定したBaseline／Change Setを書き換えない。質問と回答はResults内だけに置き、Agent会話へ複製・転送しない。

深さ出すもの
Agent作業者AIの最終報告をMarkdown全文で表示し、変更規模はApplication所有のdiffstatで示す
Results / アプリ枠実行Task切替リスト、Skill HTMLを表示する本体キャンバス1つ、短いComposer
Results / 本体キャンバスSkillsが返すHTML文書1つ。何を見どころとするかも文書の内部構成もSkillsが決める
CodeCodeモードへ切り替え、左にFiles／Source Control、中央に通常のEditorを表示する。引用時はそのファイルの位置を開く

表示の時計は2つある。データが揃う時計と、人が見る時計。

時点データ人が見ている画面
Task開始アプリが実行Taskを開始し、Baselineを確定するAgent内だけで作業中を示す。ResultsのComposer送信からTaskは開始しない
Taskキャンセルアプリがキャンセル状態、終了時刻、そこまでのChange Setを確定するSkillsはキャンセルを推測せず、渡されたTask状態をHTML生成の入力にできる
Task終了アプリが終了状態、終了時刻、Change Setを確定するResultsは自動で開かずfocusも奪わない。Taskは切替リストへ追加できるが、HTML内の見どころ分類はSkillsが決める
HTML生成中SkillsのHTML文書は未確定アプリ枠で進行状態を示し、不完全な文書断片を成果としてキャンバスへ流し込まない
HTML生成完了SkillsがHTML文書1つを返すアプリは本体キャンバスの文書を一度に差し替える
HTML生成失敗アプリが持つ実行Task、Baseline、Change Setは残すアプリ枠で生成失敗を示し、Agent報告をキャンバスの代替にしない
Results質問送信選択中の実行TaskとSkill HTMLを参照する質問をスレッドへ追加Results内で回答を待つ。Agent会話、実行Task、Skill HTMLは変更しない

アプリとSkillsの境界

枠はアプリ、中身はSkills。Skillsを差し替えても人がResultsを読む手順が同じならSkills。手順や枠が変わるならアプリ。

側持つもの
アプリ実行Taskの開始・終了・キャンセル、Baseline、Change Set。ResultsではTask切替リスト、本体キャンバス1つ、その下の短いComposerと、HTML文書をそのまま表示する処理を持つ。自動ではResultsを開かない
Skills本体キャンバスへ返すHTML文書すべて。何を一つの見どころとして分類するか、どの実行Taskをまとめるか、どんな節・文章・図・引用を使うかを決める。アプリの必須部品をHTML内へ追加しない

第一完成の出力契約はHTML文書1つ。Task切替リスト、キャンバス自体、短いComposerというページの枠はアプリが持ち、HTML文書内のレイアウトは解釈しない。

現在の設計判断

状態判断理由
決定Agent／Resultsの役割を分離Agentは作業指示、Resultsは確定済みの成果確認と質問に使う
決定Results専用の質問入口を置くAgent Composerと共有せず、選択中の実行TaskとSkill HTMLをscopeとしてResults内へ送る
決定Workspace配下にSessionを表示Cursor型の会話管理と複数Repository対応を両立する
決定通常時の左サイドバーは折りたためる展開時はWorkspace／Session一覧を表示し、折りたたみ時もNew Chat／Searchと再展開操作をアイコンレールに残す
決定会話検索とコード検索を分離Agent／ResultsのSearchは会話履歴、コード検索はCodeモードへ切り替えた左サイドバーで扱う
決定Agent／ResultsをSession内で切り替える同じSessionの独立タブとし、会話を共有しない
決定Codeは同じWindowのモード切替Codeを押すと左サイドバーの内容と中央表示を切り替える。Code中はAgent／Resultsタブを出さず、もう一度Codeを押したときだけ直前の表示へ戻す
決定左サイドバーの席は一つAgent／ResultsのSession一覧とCodeのFiles／Source Controlを同時に表示しない
決定設定は共通の左下の歯車から開く中央にTheia / ワークスペース設定を開き、Sessionは変えない。Code中はEditorへ設定タブを追加し、第一完成点ではPoiesis専用設定画面を作らない
決定Files／GitはCodeの補助ペインCodeへ切り替えた左サイドバー内でFilesとSource Controlを切り替え、コードとDiffは中央Editorへ表示する
決定FilesにCompact Composerを置かないファイル閲覧・編集に集中し、追加依頼は選択状態を保持してAgentへ戻って行う
決定1 SessionにN実行Taskを紐づけるTaskの開始・終了・キャンセル、Baseline、Change Setはアプリが独立して保存する
決定実行Taskと確認単位を分離Resultsで何を一つの見どころとして分類するかはSkillsが決め、実行Taskとの1対1を要求しない
決定Resultsは最小契約だけを固定実行Taskの切替、本体キャンバス1つ、短い独立ComposerをUI契約とし、引用は任意とする
決定キャンバスの中身はSkillのHTML第一完成ではSkillsがHTML文書1つを返し、アプリはその文書を表示する枠だけを持つ
決定Markdownを必須にしないMarkdownは将来の入力形式、またはHTMLへ変換するSkillとして追加できる
決定本体の節構成は固定しない複数の変更見出しや定型の比較をアプリから要求せず、SkillsがHTML文書として構成する
決定Resultsは確定した変更を確認する画面必要なときだけ開き、変更内容を見て質問できる
決定Resultsの入力は「見ながら聞く」入口選択中の実行TaskとSkill HTMLを固定scopeとして独立スレッドへ送り、回答もResults内に置く
決定変更要求はResultsで実行しないAgentタブで依頼できると案内するだけで、自動遷移、自動投稿、自動Task開始を行わない
決定枠はアプリ、中身はSkillsアプリはTask切替リスト、キャンバス、Composerだけを持ち、SkillsがHTML文書の表示全体を持つ
決定Skill HTMLは揃ってから出す生成中に不完全な文書断片を流し込むと、確定した成果に見えやすい
決定根拠は引用で足りる「このファイルのここ」を示せばよい。Task Change SetのCode DiffはResultsの必須契約ではない
決定解析の足し算はSkillsに委ねるカテゴリ、重要度、Confidence、Coverage、Intent比較は固定しない。なくても読める
